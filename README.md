# 可可子人格管理 2.2.0

固定核心人格，自动积累群内表达、同 QQ 跨群相处记忆与事件时间线。适配现有 `astrbot_plugin_access_gate`，只处理 OneBot/NapCat 的 QQ 群聊。

## 工作逻辑

**收到允许学习的群消息 → 保存有来源的样本与已发送回复 → 后台分批提炼记忆和表达经验 → 本轮按话题本地召回少量相关内容 → 发送后记录实际使用与明确反馈。**

记忆与表达分开管理。记忆回答“这个人明确说过什么、什么时候发生、什么条件下成立”；表达回答“这种情境下怎样接话、什么时候收尾、什么时候不用这个说法”。核心人格继续由人工管理，学习结果不自动覆盖它。

- **记忆**：整理为三类短期记忆和四类长期记忆，保留来源、置信度、主观判断及实际原话。未知长期分类先暂存，管理员确认分类后才生效；知识另需达到核实门槛。旧记忆、索引、时间线和人工纠正继续兼容。
- **表达**：支持短表达、句法习惯、接话与收尾三类，每条保存具体情境、适用意图、关键词、避用条件和原文证据。一次出现可形成候选，经人工审核或满足多人多日门槛后启用；编辑过和因负面反馈降级的经验必须人工复审。
- **学习材料**：按时间间隔、回复关系和本地话题重合组织有限片段，包含实际发出的机器人回复、匿名说话者和现有记录，避免只看孤立句子。记忆与表达有独立队列；同时启用时，一条互动可以分别提供两类材料。机器人回复可作自我反思与情绪证据，不能证明用户确认过事实或证明某个说法优秀。
- **应用与反馈**：本地选择 0～2 条相关经验，认真求助/专业问题抑制表达注入；确认发送才开始冷却，同文表达跨群去重。只有短语字面出现才记作实际短语使用。明确的“这样说很自然”“别这么说”才可参与反馈；“哈哈”、沉默、引用和无法定位到某条经验的评价不会给所有规则加分或扣分。
- **成本**：每轮默认记忆 800 字符、表达 400 字符，另受总计 1800 字符上限约束，无相关内容时不注入空壳提示。普通聊天不增加模型调用，学习仍在原有后台预算内进行。

当前检索与情境匹配是本地词法规则，没有向量模型；同义词、反讽和复杂指代可能漏匹配。句法是否实际采用不自动判断。反馈限同一用户在十分钟内对最近已发回复的明确评价；框架没有可靠的发出消息 ID 时不关联引用反馈。负面累计至少两次且多于正面，经验会转为待复审。是否更自然需要真实群聊观察，测试通过不能替代该评估。

代码按职责拆分：`dialogue.py` 管理来源、双队列、实际回复和反馈；`memory_store.py` 管理兼容记忆与索引，`classified_memory.py` 管理七类生命周期及审核，`memory_types.py` 管理分类 JSON 协议；`expression_store.py` 管理表达审核、版本和使用；`retrieval.py` / `expression.py` 做本地匹配；`chat_context.py` 组装有限上下文；`runtime.py` 保留授权复核、批处理和预算调度。`storage_base.py` 保留兼容存储与用量账本，`storage.py` 提供统一入口，`migrations.py` 管理迁移。

## 从旧版升级

从 0.x 升级会先生成 `persona.before-v1.sqlite3`，从 1.0 升级会先生成 `persona.before-v2.sqlite3`，再事务化建立新增表。备份使用 SQLite backup 并校验，不覆盖已有文件。旧编号、状态、证据和预算记录保留。2.0 默认启用门禁放行群的互动记忆，已配置的禁用群仍有效；公共记忆读取改为默认关闭。需要延续明确选群模式时，将 `memory_default_enabled` 关闭。

升级后，旧短表达继续按原语境匹配；新表达使用条件化结构。旧表达版本只能恢复当时记录的启用状态，1.0 新版本会恢复完整表达内容。固定偏好与低置信候选可在管理页调整。

若需退回 0.x，先停止插件，保留升级后的数据库，再恢复升级前备份和旧代码；不要直接用旧代码打开升级后的数据库。备份应作为独立的历史数据副本管理，应用内“遗忘”不会擦除外部备份。

## 七类记忆、分类审核与用量

默认每个群积累 **20 条已回复用户消息** 后整理；包含对话时间、稳定说话者标记、消息编号、原文和已发送机器人回复。运行状态显示“正在思考”，默认向来源群提示一次；异常、取消和拒绝入库都会退出思考状态。模型只返回 JSON，不携带工具和主聊天历史。无效 JSON 保留批次等待重试；无新增记忆可返回空数组。

| 属性 | 保留规则与证据 |
| --- | --- |
| 时效性短期 | 单条 `ttl_seconds`，例如 300 秒、1800 秒，从原消息时间计算；到期停止召回并清理正文和证据。 |
| 日常短期 | 保留到下次入梦；默认每天北京时间 04:00 清理，也可关闭定时或手动入梦。入梦本身不调用 AI。 |
| 缓存短期 | 每个用户默认最多 30 条（跨群合计，读取仍隔离来源），满时清理最旧记录；容量可调。 |
| 长期关系 | 主观关系、称呼、人物信息、对方原话、我的心情；区分本人陈述、转述、推测及准确性。关系不代表对方认同。 |
| 长期事件 | 我的情绪波动事件；需要实际回复证据、心情与强度，默认最低强度 0.7，可调。 |
| 长期知识 | 默认 3 次独立确认，按“同一来源群、主题、相同摘要”聚合；同一人同一天只计一次，重复来源不计。未达门槛先暂存；管理员可在面板直接确认并灌输知识。 |
| 长期自我认知 | 根据实际已发送的言语行为提炼；以独立特性为主题，较新认知替代本群同特性的旧版本，保留历史。不会自动改写核心人格。 |

分类器由名称、七种属性之一、关键词、描述和默认有效期组成。模型遇到新类型时提交分类定义：短期类型自动通过并在待核对区显示；长期类型在管理员确认前不召回。管理页可以修改分类并确认，同步迁移该类型已有生效及暂存记忆；迁移到知识类仍受确认次数约束，迁移到短期类立即应用清理规则。修改已失效或已遗忘内容不会自动复活。

“记忆整理与分类”提供按用户、类型、状态筛选和翻页，查看证据、编辑正文、主题、来源性质、置信度、心情、情绪强度、标签、人物细节与有效期。分类和单条编辑都有版本校验。自我认知和知识按人格保存，也保留来源群；管理员灌输知识是公共知识，读取仍需开启公共记忆。未知人物只能作为报告者的转述，不猜测身份。

**1 Mtokens = 1,000,000 tokens**。记忆整理默认每日 **0.06 Mtokens**、每自然月 **1.8 Mtokens**，按北京时间换日/换月；0 表示关闭模型整理。输入与输出一起计入，未报告完整用量时保守估算，失败、取消及在途请求同样占用预算。每日、每月、原有全局/群学习预算在同一事务中预留；未发出的预留释放，重载不重置已用额度。面板展示每日/月度占用及上限，实际供应商计量可能高于预估，超过后阻止后续调用。

知识的“确认次数”是可审计的来源次数，并不等于外部事实核查；摘要表达不同不会自动合并。自动摘要、情绪和准确性判断仍需管理员核查。完整原对话有独立的采集保留期；短期条目清理不等于擦除尚在保留期内的对话原文或外部备份。

## 启用

1. 将本目录放入 AstrBot 的 `data/plugins/`，保留现有独立白名单门禁和其他插件配置。
2. 在本插件配置中选择可可子实际使用的**原生人格 ID**。默认值为 `可可子`；若实际 ID 不同，必须重新选择。
3. 自动发现 QQ 群；门禁放行、使用目标人格的群默认启用互动记忆，可在群列表关闭。旁听表达、跨群表达和公共记忆读取默认关闭，按群开启后保存设置。
4. 在“忽略的QQ号”加入菌菌等其他机器人账号。自身消息自动排除；OneBot 无可靠机器人标志时，其他机器人需通过此配置排除。
5. 选择后台学习模型，或留空跟随源群当前聊天模型。默认每日全部群最多 12 次 / 60000 tokens、每群最多 4 次 / 20000 tokens；失败和超时保守计预算。任一相关预算设为 0 即停用模型抽取，简单明确偏好仍可本地提取。
6. 重载插件，在插件详情打开“人格管理”。49 项配置均可在“设置与方向”编辑，与原生配置共用数据；记忆、分类及审核在“记忆整理与分类”管理。
7. 按实际模型供应商的价格表填写北京时间低价时段，再填写进化方向。低价时段默认留空，不预设任何公司的折扣时段；空列表全部按常规价处理。

安装和启动不会改写原生人格。管理页面会读取并备份当前核心；“载入推荐核心”仅载入草稿，点击保存才更新该原生人格的 `system_prompt`，工具白名单、开场对话及其他人格不变。推荐底稿在 [persona_seed.txt](persona_seed.txt)，按已确认设定整理，保存前可编辑。

声明最低 AstrBot 版本为 4.24.0，使用临时 `TextPart`、人格管理、插件 Pages 与后台 LLM 接口；实现依据当前官方文档及源码，部署版本的完整兼容性仍需实际联调。运行时无新增第三方依赖。

## 触发与共存

- 门禁负责权限、开放时段、称呼、@ 和提及判断。本插件不调用 `stop_event()` 或 `should_call_llm()`；只在模型整理开始前向已授权来源群发送简短思考提示，可关闭。
- 群目录监听优先级为 10002，在现有门禁前仅登记群元数据；不读取聊天正文、不设置路由位、不调用模型。旁听正文采集仍为 9998，低于现有门禁的 10000/9999，只有活动门禁可见、群消息未被停止、实际人格匹配且勾选对应群时才采集。
- 门禁自定义唤醒开启时，互动依赖可信事件标记 `access_gate_original_text`。关闭自定义唤醒、使用 AstrBot 原生 @ 时，要求已唤醒、当前缓存的主聊天请求匹配，并再次复核群门禁、会话权限和目标人格；实际发送回复后才记录。单独匹配指令或其他插件的 LLM 请求不视为相处互动。
- 复核会话插件集和会话级禁用状态；其他插件设置的显式 `provider_request` 不注入。只确认普通主聊天的已发送结果，或有已发送内容的流式完成结果；错误与未完成输出不记作相处成功。
- 自身标记的临时上下文可重复替换，其他插件的上下文、原始问题、图片、工具列表、系统提示和对话历史不改动。
- **私聊始终跳过**：不采集、不检索、不注入、不调用学习模型，也不会中断 RTLink 绑定等现有私聊指令。
- 本插件不新增聊天口令或 LLM 工具。管理操作集中在登录后的 AstrBot Dashboard，避免在群里展示整份人物档案。
- 不会接管 RTLink、六爻、五行、紫微的计算、输出、额度和权限。已有专业插件可自行发送结果。

默认 Agent 的触发取决于门禁处理后的 `is_at_or_wake_command` 和 `call_llm`；框架的普通监听器可能设置 `is_wake`，不能仅靠该标记判断人与可可子的互动。本插件只读上述路由状态。

“私聊不消耗 token”指本插件对私聊的新增调用为零。本插件不会修改现有门禁：如果门禁配置另外放行了私聊 AI，主聊天或其他插件仍可能调用模型。保持全机器人私聊不聊天，需要现有门禁继续禁止私聊 AI，同时保留需要的私聊命令入口。

当前门禁适配使用工作区 Access Gate 的实际处理函数作本地组合验证。后台权限复核使用它现有的只读配置方法；无法确认门禁接口、会话授权或人格时跳过学习，不另外启动触发判断。框架确认发送完成不等于 QQ 端已送达。

## 自动群目录与群开关

机器人收到群消息后，目录记录群名、群号、平台连接、机器人 QQ、首次/最近发现时间，以及接口可用时的成员总数。这里只保存群元数据，不保存群成员名单、发送者或聊天正文。群目录与人格选择、学习暂停和门禁放行无关；关闭本插件总开关或平台/会话未加载本插件时不再发现新群。框架在插件运行前就过滤的消息不可见，因此目录不等于机器人加入的完整群名单，也不会主动拉取历史聊天。

群名优先读取真实事件元数据，并在后台调用 OneBot `get_group_info` 补全与刷新；不调用 `get_group_member_list`，不调用模型。成功缓存 24 小时，失败后至少 1 小时才在后续群消息中重试；单次超时 5 秒，并发最多 8 个查询，不阻塞门禁等待网络。最近发现时间按约一分钟粒度写入。群名未知时显示“群名待获取”，已有名称查询失败时保留缓存。

- “旁听学表达”控制该群的表达采集、后台抽取和表达注入。
- “互动记忆”控制采集、整理和本群召回；“允许读取公共记忆”独立控制跨群召回。同 QQ 的记录保存在共同用户身份下，保留来源群与平台，关闭公共读取时先限定本群再检索和去重。
- 旁听与互动开关独立；勾选只修改草稿，保存后生效。关闭后保留历史数据，不补收关闭期间的正文；在途旧学习结果作废。修改这里的开关不会放行原有白名单门禁或唤醒规则。

升级时已有群补入目录。`memory_default_enabled` 默认开启；禁用群优先。关闭默认启用时使用 `memory_groups` 精确选群。群开关会同步修改 `memory_disabled_groups`；手动开启某群只解除该群、该连接的排除。

开关按“平台连接 + 群号”保存。同一群出现在多个连接时分别展示；关闭其中一个连接会把旧的通用群号规则收窄为其余已发现连接，避免同时关闭其他连接。不在列表中的高级配置条目会保留。

## 跨群表达与群标签

每个群卡片新增“群标签”和“允许使用跨群表达”。标签用于描述群的性格、话题和能力领域，例如 `太鼓达人、闲聊、技术交流`；最多12个，每个最多24字。直接在群卡片填写，无需输入群号，保存设置后生效。标签不会改变人格身份、权限或真实工具能力。

- 跨群表达开关默认关闭，旧群、新群均不自动开启。关闭时保持原有本群表达逻辑；本群表达仍由旁听开关控制。
- 当前人格下所有**已启用**表达自动参与全局匹配，包括升级前已经学会的表达；候选、停用和遗忘的表达不参与，不把多个群的证据合并以绕过启用门槛。
- 全局开关与采集开关独立。可以只使用跨群表达而不旁听、不记录人物记忆；仍须通过现有门禁并使用目标人格。没有群标签时不使用外群表达。
- 跨群匹配使用本地关键词规则：目标群至少一个标签出现在梗的含义或适用语境中，并且不命中避用语境，随后再检查当前对话语境。英文标签忽略大小写并检查词边界，不做额外模型语义分类；同义说法未命中时会保守跳过。建议填写明确的话题和性格关键词，避免用长段指令作为标签。
- 优先选择本群表达，再补充匹配的外群表达；相同文本去重，每轮合计最多2条并限制近期重复。专业/求助关键词抑制及动态上下文长度上限继续生效。读取和匹配不额外调用模型，注入的文本仍计入主聊天输入。
- 全局库引用原表达，没有复制出另一份数据。停用、遗忘或回滚原表达会同步影响其全局可用性；其他群独立学会的同文表达仍有自己的生命周期。关闭某源群旁听只停止该群采集及本地使用，已有表达仍可供其他已开启跨群表达的群匹配；要全面撤回某条表达，请在“群表达”中停用它。
- 开关和标签按平台连接及群号保存，支持不同连接分别配置。原生高级字段是 `global_style_groups` 和 `group_tags`，与面板共用配置、版本冲突及保存校验机制。修改标签或关闭全局开关后，后续请求立即使用新配置。

## 两条学习路径

**旁听**：仅白名单群，读取顶层文本，不展开引用、转发或附件。样本只可生成群表达候选，不能生成个人档案。候选须有真实文本证据，经过规则/身份/敏感信息检查；同一表达至少来自 3 人、2 个北京时间日期、5 次独立出现，同一用户同小时只计一次。每群每天最多自动启用 2 条，最多保持 20 条活跃表达。自动启用门槛为固定值，管理员可审核单条候选。

**相处记忆**：仅采集门禁实际放行、目标人格成功发送回复的群互动。已回复消息与实际回复分别标记来源，按群累计，默认达到 20 条用户消息后批量整理。简单明确称呼和回答偏好可立即本地提取，该段对话仍保留在待整理队列。

新协议允许有原话支持的摘要，逐条核对引用和可信说话者；未知第三人不能绑定到猜测的 QQ。转述和主观判断明确标注未核实。机器人实际回复可作为自我认知、情绪和关系背景证据，不能作为用户确认知识的证据。旧版个人事实抽取仍保留更严格的第一人称原文规则。

### 跨群人物与群内表达

- 人物：`目标人格 + 可信 QQ 号`，记录保留来源作用域。跨群读取须目标群单独开启公共记忆，不能据昵称合并账号。
- 表达：`人格 + 平台实例 + 机器人QQ + 群号`。默认群 A 的梗不注入群 B；目标群开启跨群表达并通过标签及对话语境匹配后可以复用。
- 熟悉程度仍按跨群去重的有效互动天数供管理页查看；不再每轮注入关系等级或要求扮演熟络，不改变办事质量和权限。
- 每轮只读取当前人的小量认知及相关事件。来源群留在管理视图，普通聊天上下文不附来源群或原始 QQ。
- 旧记忆同样受公共读取开关限制；缺少来源证据的旧记录不猜测群归属。管理页仍能按用户查看完整记录。

## 时间线

区分原消息发送时间、记录时间、事件发生区间及状态有效时间。全部时间以 UTC 秒保存，解析和展示采用北京时间，不依赖服务器时区。

支持今天、昨天、前天、明天、上/下周及星期、周末、上/下月、明确日期与常见时刻。相对时间锚定原消息，不按后台处理时间重新解释。未知、含糊或非法日期保留未知；时间范围结束为不包含该时刻的边界。

例如 20 日说在练幽玄，28 日说改练万戈，29 日才处理到 20 日的旧消息，当前目标仍为万戈。计划、进行中、完成、取消分开记录，日期到了不自动完成。当前目标超过 30 天会在注入时标注需要确认。

当前练习与未来计划分别保留；去年、前年等按原消息解析。本周、本月等包含原消息时刻的状态按消息先后更新，不按周一或月初抢占顺序。含糊、非法或无法定位的历史时间只保留在线索中，不据此改写当前认知。合法日期不会误当电话号码过滤。跨群追问“之前在练什么”可召回旧目标及偏好，避免只查经历类记录。

明确纠错可在管理页定向修改正文、时间和状态；旧记录标为已纠正，历史可追溯，普通回复不再使用被纠正事件。未另填时间时保留原事件时间，修改历史记录不会让它抢占当前状态。后台提案只能使用提供的记忆句柄定向纠错，入库时校验归属和版本；待确认的纠错不会提前停用原事实。当前没有把任意自然语言的计划、取消和完成自动合并为同一个任务的能力，会保留有来源的阶段记录供理解和管理。

纠错后原证据只供审计，不再送入自动学习，避免下一批换个主题重新学回旧说法。时间字段未改或留空都会保留原锚点；更改时间时建议使用明确日期。0.1.0 数据库会自动补充时间表达字段，保留既有记录。

## 价格时段与进化方向

这里的高低峰由**配置的模型价格时段**决定，不按群消息活跃度判断。支持多个北京时间时间窗、跨午夜，例如 `23:00-07:00` 仅为格式示例，并非 DeepSeek 当前价格声明。时间为 `00:00`～`23:59`，起点包含、终点不包含；起止不能相同。低价时段留空表示无低价时段，允许后台学习时间窗留空则表示全天允许。

| 配置 | 常规价默认 | 低价默认 |
| --- | --- | --- |
| 同群互动记忆积累门槛 | 20 条 | 20 条 |
| 群旁听积累门槛 | 20 条 | 5 条 |
| 同类批次学习间隔 | 30 分钟 | 5 分钟 |

记忆整理统一受 `memory_batch_threshold` 门槛约束，低价时段不降低门槛；旧常规/低价互动条数设置只为配置兼容保留。旁听表达仍可在最长等待后处理较小批次。允许学习窗口、冷却、权限和预算同时生效。

“进化方向提示词”最多 4000 字，用于指导后台学习的关注点、表达取舍和应减少的习惯，例如：

> 闲聊简短自然，减少复读和固定口癖；关注群友太鼓练习目标与后续进展。专业问题重视事实依据和当前工具结果，不学会编造能力或结论。

页面可载入参考方向到草稿，保存后才生效。方向不会自动改写核心人格，也不会直接注入主聊天；学习内容仍须有真实样本证据，不能靠方向提示新增事实、工具能力或权限。修改方向和学习设置会使正在处理的旧结果失效；已经发出的模型请求仍可能产生用量。

## 成本、保留期与后台生命周期

- 普通回复只执行本地数据库读取，不新增前台分类模型调用。
- 每轮动态上下文默认最多 1800 字符，按完整条目裁减。专业/严肃请求抑制表达注入，确认发送后默认冷却一小时，重启后仍有效；单纯检索不会消耗冷却。
- 后台每 30 秒检查一次，每轮最多调用一次模型。记忆按群合批，表达按来源群合批，分别冷却。默认最多 30 条、原文总计 12000 字符；门槛不能大于批次上限。
- 提供商调用使用独立提示、空历史、无工具；请求输出上限默认 1200 tokens，可设 256～4096，实际参数执行与计费仍取决于提供商。插件另限制返回文本及候选数。
- 调用次数与 token 预算按北京时间日持久化，重载不清零。发出前原子预留全局与群额度，成功后按供应商报告结算；未获得完整用量、超时或取消则保守占用。确认没有调用模型的预留会释放；进程中断后的未知预留保留，不冒充零消耗。
- 预估采用请求 UTF-8 字节数、消息包装余量和输出上限，因此会比常用 tokenizer 保守；它不是供应商账单或任何模型的绝对上界。积压达到整理门槛后，单批预估超出剩余额度时自动缩小批次并重新预留，不提高用户限额，不提前处理尚未入选的来源；单条也放不下时显示具体阻塞原因。提供商额外内容或不遵守输出上限仍可能造成实际用量高于预留。
- 学习总览分别显示已报告输入/输出、估算占用、在途预留、今日调用、近 7 天趋势、各群今日用量和最近学习的采纳数。旧版仅有调用次数、没有 token 数据的记录标为未知；切换目标人格不清空全部群的总预算。
- 排查“没有记忆”时，先看总览的**已采集原文 / 待整理对话 / 生效记忆 / 待确认记忆**，再看最近采集与调度原因。采集诊断只保留本次插件加载以来的状态、群号和时间，不保存聊天正文；待整理数量来自持久化队列。运行版本和页面版本应一致，更新后需重载插件并重新打开管理页。没有模型调用记录不代表没有采集，知识或新长期分类待确认也不等于未保存。
- 这里只统计本插件后台学习。动态上下文会占用主聊天输入，主聊天与专业插件的完整用量仍交给已有统计插件，不重复计算为后台学习。
- 每次调用前及结果入库前复核源群门禁、插件启用、当前人格和学习配置；撤回后不新增调用，已发出的调用可能仍计费，但旧结果不会入库。全局与群预算一起原子预留，并发调度不重复提交同批；被禁用群的大量旧样本不会堵住后续群。
- 原文过滤后为空，或旁听有效样本不足门槛时不调用模型。
- 暂停/关闭学习停止新增采集与抽取，原文到期清理继续运行，已有有效记忆仍可使用。
- 原文默认旁听 48 小时、互动 7 天。实际回复随关联原文到期清理；已采纳的短记忆、表达、短证据片段、来源标识与互动日期单独保留，支持显式遗忘。请勿把原文保留期理解为全部派生数据的保留期。
- 移除旁听白名单后停止该群新采集、抽取和表达注入；已有记录保留供管理。停止插件时取消并等待后台任务。

## 主聊天 AI 记忆工具

在门禁已放行、启用互动记忆且选中目标人格的 QQ 群中，主聊天 AI 可以使用下列工具。工具使用同一份 SQLite 记忆库，不写 `memory/*.md`；无需额外配置 API Key。AstrBot 人格若使用工具白名单，需在目标人格中允许这四个工具，插件不会改写原生白名单。

| 工具 | 功能 |
| --- | --- |
| `persona_memory_search` | 查找当前发言者和当前群有权读取的知识、自我认知，或按真实编号读取详情；返回状态、编号和版本 |
| `persona_memory_write` | 用户明确要求时记住、纠正或遗忘单条记忆；修改前先查询编号与版本 |
| `persona_memory_status` | 查询当前群整理状态；用户要求整理时检查本群批次，仍受数量、时段、冷却及预算限制 |
| `persona_memory_admin` | 真实 AstrBot 管理员明确确认知识或手动入梦；权限由事件和平台配置核验 |

例如提供完整手法原文并说“记住这段太鼓手法”，AI 使用 `knowledge` 类写入，普通来源继续累计核实，待核实时不能回答“已经成为确定知识”。管理员明确确认灌输时才可使用 `knowledge_confirm`。说“把刚才那条错误记忆改成……”或“忘掉这条记忆”时，先查询目标，随后携带版本修改或遗忘；不会按昵称操作其他用户。

直接写入和纠正只接受本次发言者原文中的事实与逐字证据，不从引用、转发或工具结果冒认事实；需要补原文时会返回失败原因。事件和自我认知需要真实已发送回复作为证据，继续由后台整理。即使记忆库为空，也会提供记忆工具路由说明；若工具没有开放，AI 应说明无法主动执行，不能改用文件写入冒充成功。

主动操作返回实际记录状态。公共记忆默认关闭，查询和单条详情同样受该开关限制；普通用户不能纠正或删除他人的记录、知识库或自我认知。分类确认、核心人格、群权限与预算仍在控制台由管理员管理。手动入梦清理当前人格所有群的日常记忆，须管理员明确授权，不会保存未提交的配置草稿。

主动写入/查询不额外调用模型；执行整理使用既有后台学习账本，主聊天本身的 tokens 仍由 AstrBot/用量统计记录。用户要求立即整理并不等于满足门槛或已完成，工具会返回实际调度结果。

## 管理页面与恢复

所有 API 需 Dashboard 登录，且核对目标人格、记录和群作用域。页面通过官方 `AstrBotPluginPage` bridge 访问，不使用外部 CDN 或单独监听端口。

- 核心：编辑、查看版本、恢复旧版本；仅人工操作修改。
- 人物：`目标人格 + 可信 QQ 号`，记录保留来源作用域。跨群读取须目标群单独开启公共记忆，不能据昵称合并账号。
- 群表达：查看候选/已启用表达及来源，编辑条件和形式、审核、停用、回滚内容版本，查看实际对话与明确反馈。
- 学习总览：暂停/恢复，查看用量、预算、样本门槛、当前价格时段、等待原因和近期学习结果；运行状态保留最近上下文引用编号。
- 设置与方向：全部 49 项配置按六个分区编辑；顶部流程可直接跳转整理节奏、生命周期和分类审核。

| 配置分区 | 可视化与编辑内容 |
| --- | --- |
| 整理节奏 | 总开关、目标人格、对话积累门槛、单批容量与思考提示；数量支持滑块和直接输入 |
| 记忆生命周期 | 三类短期和四类长期卡片；实时预览缓存容量、入梦时间、知识核实次数与情绪门槛，跳转分类器调整有效期和审核；显示最近入梦时间，支持确认后立即手动入梦 |
| 模型与预算 | 模型、输出限制、日/月 Mtokens 用量条；折叠查看共同生效的调用次数和单群预算 |
| 群与共享 | 展示门禁、记录与共享路径；逐群选择互动记忆、旁听、公共记忆和跨群表达，保留手动群范围入口 |
| 表达与方向 | 成长方向、每轮表达数量、冷却与召回长度 |
| 高级选项 | 旁听积累、允许/低价时段、原文长度和保留时间；旧版兼容参数单独折叠 |

卡片与预算限额随当前草稿更新，**点击保存才生效**。切换分区不丢失草稿，各分区显示修改数量；无效参数会定位到对应分区。用量缺失时显示未知而非零，零限额显示停用；预算占用包含预留和估算，不等同供应商精确账单。页面适配手机横向分区导航，不提供私聊启用项。

刷新状态会保留未保存的人设与配置草稿。其他页面改动配置后会提示版本冲突，需重载并核对草稿，避免静默覆盖；保存失败不显示成功。自定义页面使用 AstrBot 的原生配置保存接口，不另存第二套配置或 API 密钥。

遗忘会清空相关正文/派生内容、撤销相关表达并保留非正文重放标记；已进入处理中的旧结果因版本变化而失效。暂停切换、纠错和表达回滚也使旧后台任务失效。回滚表达不会倒退个人时间线，已遗忘内容不会被版本恢复复活。

备份前先暂停/停止插件；数据位于 `data/plugin_data/astrbot_plugin_persona_manager/persona.sqlite3`。SQLite 使用 WAL，运行时不能仅复制主数据库文件充当一致备份。恢复外部旧备份可能恢复备份时的数据，不属于应用内回滚保证。
